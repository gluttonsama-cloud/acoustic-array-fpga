# 主应用场景与转向条件

> 文档类别：规划与进度｜状态：用户最新确认的现行方向。[返回文档索引](../文档索引.md)。

## 定位与优先级

项目名称：基于FPGA的多声源实时空间分离与弱声定向增强系统。

用户最新澄清以“多声源空间分离＋定向拾音”为技术核心，以“复杂噪声中弱声定向增强”为重点演示和应用表达。搜救中的呼救/敲击是应用示例，不将产品限死为搜救设备；也不擅自将其改为仅服务会议的产品。此前把搜救与自动弱声搜索写成必须完成主线的解释过窄，以本次澄清为准。

| 层级 | 要实现或验证的内容 | 定位 |
|---|---|---|
| 核心交付 | 多通道同步采集、多波束空间处理、多声源方向展示/选择、多路定向音频输出、FPGA实时链路 | 第一优先级；定位/多峰检测分阶段闭合，人工指定方向仅是开发步骤 |
| 重点增强演示 | 加入较强干扰，展示指定较弱目标的增强及边界；可用语音或敲击 | 第二优先级，复用同一技术底座，不另造一套搜救系统 |
| 应用示例 | 复杂环境定向监听、多人多声源拾音、呼救/敲击辅助监听等 | 用于解释价值；每项能力按实测范围表述，不等于产品可靠性已验证 |
| 非核心承诺 | 自动识别呼救语义、灾害搜索流程、穿透废墟、地下定位、救援级漏检保证 | 不作为本阶段强制交付；确需新增再明确范围 |

截图中的DAS、固定零陷是候选路径，不是必须保留的算法；“两个月落地”“固定零陷足够”等是待验证判断，不作为工期或效果承诺。允许依据现有混响/失配证据替换算法或调整阵型。

## 验证与近期安排

先形成多方向输出的可运行核心，再把稳健性和弱声演示接入同一链路。已有方向/混响失败证据用于选择改进，不继续重复扩展等响三人解释性扫描。

当前一个真实门敲击＋一个强语音干扰的固定对照继续执行，用途是检验目标保护和干扰抑制，不能代替多声源核心验收。其余呼救语料、敲击语义分类及救援事件检测不作为该工作包前置条件。敲击素材不是被困者实录，普通朗读也不是呼救。

弱声程度按同一参考通道、目标活动段的实际SIR/SNR定义；同时报告目标失真、全带与带内结果，音频采用共同增益。人工已知方向、自动估计方向、离线仿真、实录和板端分别记录。弱声输出可以由人试听，不能自动写成已经识别呼救。

现有16麦线阵与候选FPGA仍需通过算法、阵型对照及实际采集/综合证据确认。第一版可限定覆盖角、距离、声源间隔和混响范围，这属于确定可用边界，不等于换应用。

## 调整和转向条件

先区分核心能力不足与某个增强演示困难。若弱声演示暂时未达到目标，不因此否定多声源核心，也不无限增加搜救专用任务；应报告差距，按代价决定改算法、改阵列或调整演示条件，不能悄悄降低已承诺指标。

只有合理的有界算法/硬件修正后仍无法在明确使用边界内完成核心交付，或者超出实际成本/工期，才提出整体转向建议，由用户决定。当前证据不足以否定技术核心，也不足以宣称已能实际救援。
