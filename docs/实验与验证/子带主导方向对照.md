## 候选和TDD过程

候选将每20帧、每4个连续频点当作一个单元，每单元在逐帧PHAT后只投一个主导方向，再跨时间和子带累积。它直接检验“侧向声源是否至少在部分局部单元占主导”，不再从一张宽带图选三峰。

新测试先因`subband` 模块缺失而产生有效RED，再以最小实现转为GREEN。独立Python审查在真实场景前发现一处高优先级错误：逐帧防溢出尺度被错用于块能量门控，破坏了跨帧物理功率比。新增跨帧强/弱子带回归测试先复现失败，再改为全块共同尺度计算能量；PHAT仍逐帧缩放。修复后审查批准，才运行四场景。

## 四场景结果

5°容差一对一匹配；每条件三个真实目标。基线为相同输入的静态SRP-PHAT。

| 条件 | 静态基线匹配/虚警 | 子带输出 | 子带匹配/虚警 |
|---|---:|---|---:|
| 2米、15°间隔 | 2/1 | 0° | 1/0 |
| 2米、45°间隔 | 2/1 | 0° | 1/0 |
| 3米、15°间隔 | 1/1 | 0° | 1/0 |
| 3米、45°间隔 | 2/1 | 0° | 1/0 |
| **合计** | **7/4** | — | **4/0** |

预定关口为至少9/12匹配、虚警不超过2，且每场景不得比基线退化。候选仅4/12匹配且三个场景退化，明确未通过。560帧同长静态对照仍为7/12匹配、4虚警，排除了丢弃末尾一帧导致差异。

## 从固定输出得到的原因边界

每个场景共28个完整时间块×12个子带=336个候选单元。事后只读保存的子带谱和投票，不改正式结果：

| 条件 | 通过单元数 | 真值方向支持率（左/中/右） |
|---|---:|---|
| 2米、15° | 55 | 0 / 6.35% / 0.10% |
| 2米、45° | 27 | 0 / 6.45% / 0.60% |
| 3米、15° | 43 | 0.20% / 6.35% / 0 |
| 3米、45° | 23 | 0 / 5.26% / 0 |

侧向真值附近最多只有2/336票，绝大多数为0；中央方向获得13～18个直接票。因此单纯降低最终5%支持阈值不会召回稳定侧向源，只会更容易接受零散方向。这些数据证明当前固定子带/短块中央源主导；它们不能单独区分混响、同时发声占比、距离或阵列分辨力哪一项是唯一原因。

## 决定

按预案停止SRP峰阈值和峰累积类修补，不将本候选接入多路音频。下一步使用Pyroomacoustics的NormMUSIC和普通MUSIC作独立离线对照：明确`num_src=3`、轴顺序和角度转换，不将库调用写成FPGA已可部署。如果子空间方法在相同仿真中仍无法恢复侧向源，就要重新评估同时三源、RT0.4秒和当前阵列对自动定位的联合边界，而非继续微调检出阈值。
