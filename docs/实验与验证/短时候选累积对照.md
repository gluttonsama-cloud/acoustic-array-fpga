# 短时候选累积对照

> 文档类别：实验与验证｜状态：固定候选未通过，不接入多路音频。[返回文档索引](../文档索引.md)。

日期：2026-09-24。实现和真实场景运行前已在[实施边界](../规划与进度/自动定位与多路输出实施边界.md)固定方法、阈值、四个开发条件和通过门槛；运行后未调参或重跑。

## 要验证的修正

上一版先把3秒互谱平均再做PHAT。本候选改为每帧PHAT，每20帧（约107ms）形成一幅SRP图，对局部显著峰进行方向投票。内部峰用10°显著性邻域，±90°边界峰用30°单侧邻域；这一边界修正由实际16麦解析端射测试在场景运行前触发。每块同方向最多一票，支持率分母包含静音块。

预定通过条件是：12个目标至少匹配9个，虚警不超过2个，四个条件中任何一个的匹配数不得低于上一版。全部满足才接入多路音频。

## 结果

| 条件 | 上一版匹配/虚警 | 短时候选方向 | 短时匹配/虚警 |
|---|---:|---|---:|
| 2米、15°间隔 | 2/1 | 0° | 1/0 |
| 2米、45°间隔 | 2/1 | 0° | 1/0 |
| 3米、15°间隔 | 1/1 | 0° | 1/0 |
| 3米、45°间隔 | 2/1 | 0° | 1/0 |
| **合计** | **7/4** | — | **4/0** |

候选没有通过：虚警从4降为0，但匹配从7/12降为4/12，而且三个场景退化。560帧的同长静态对照与561帧原基线匹配/虚警完全一致，排除了丢弃末尾一帧是退化主因。

事后只读已存空间谱：四个场景的中央目标支持率为15.5%～19.0%，其他真实方向除一处45°仅3.6%外均为0。因此问题不是最终10%支持阈值稍高；当前“每块最多三个显著峰”策略在强混响三源条件中没有稳定产生侧向候选。

## 决定与实质发现

停止本候选的阈值扫描，不接入多路音频。这次实验否定了“只把PHAT改成短时后做峰累积，就能恢复三源”的具体方案，同时表明虚警与漏检必须共同评价，不能用低MAE或零虚警单独宣称成功。

下一个有界候选改为时频/子带主导方向直方图，利用语音在不同时频单元中主导源不同的性质，避免先把多源合成一张宽带图。若该候选仍不达关口，就不再围绕SRP峰阈值修补，转入MUSIC/子空间或开源定位库对照。
