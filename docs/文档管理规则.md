# 文档管理规则

状态：现行规则。适用范围：本项目人工维护的文档。用户要求：中文名称、按用途分类、有统一索引，不添加排序编号。

## 文件名与目录

- 专题文档使用“中文主题.md”，不加人为排序数字，不使用全大写英文文件名。例如“软硬件可行性与决策计划.md”。
- M1、M2、S1属于已有里程碑/场景标识，可在实验报告名称中保留；FFT、DOA等必要技术缩写也可使用。它们不是排序编号。
- `docs`根目录只放文档索引和本规则，内容按“规划与进度、架构与规范、实验与验证、技术决策、参考研究、图表”归类。不为日期或单篇文档额外建目录。
- 分类选择按用途：决定做什么放规划；约束怎样实现放规范；记录实际运行放实验；解释重大取舍放决策；外部来源比较放研究。图表跟随主题命名。
- `README.md`、`AGENTS.md`、`CHANGELOG.md`及模块`README.md`保留工具/项目约定名称，正文中文。不更改代码标识符、配置键、机器清单、源语料名或实验run目录。
- ADR已有编号保留在正文作为稳定引用ID；文件名用中文主题，不给其他文档套用ADR编号。

## 索引与当前状态

- [文档索引](文档索引.md)是专题文档的统一入口。每篇文档登记用途及“现行/阶段记录/历史”等状态；新增、改名、迁移时同一轮更新索引。
- 项目根README只概述当前状态、常用命令和主要入口；不连续追加多条“最新进展”。历史变化写入项目演进记录和CHANGELOG。
- 当前工作状态与唯一下一步以“执行看板与续接规则”为准；项目演进记录保留简短历史，项目规划维护范围与里程碑，专题报告维护详细数字。发生实质变化时更新对应责任文档，其他入口用链接引用，不重复抄写同一份指标。
- 历史报告保留当时数据、版本、失败和结论，顶部标明“历史阶段记录”。不能把历史的“尚未建立/尚未实现”误读为当前状态，也不能回改旧数字制造进展。

## 文档写法

- 新专题文档首行写中文主题，接着写状态、日期/适用版本，再给结论和阅读目的。
- 实验报告写清输入、配置、指标口径、实际结果、失败、证据路径和限制。计划中的工作标注待执行，不写成已完成。
- 技术决策写背景、选择、理由、代价及何时重新评估，引用稳定ADR ID。
- 文档之间使用可点击相对链接；仅提文件名且读者难找时应补链接。大音频、数值归档放data/artifacts，文档只引用。
- 避免复制多份正文或另存“最终版/最新版/最终修改版”；现行规范就地维护，重大历史取舍追加决策，实验结果按独立run保留。

## 修改后的核验

- 改名/移动前记录旧新路径；同步修复Markdown链接、图片链接、入口、规则中的引用及目录树。
- 普通编辑只检查受影响文档的链接、图片和内部一致性；新增/改名/迁移时检查相关索引及旧路径残留，广泛重组目录时才全量扫描。没有链接的历史引用也应保持可定位。
- 冻结的实验manifest、原始输入、历史构建产物不因文档迁移改写；必要时以迁移映射解释旧路径，维护目录不放英文空壳副本。
- 纯文档整理不升级算法版本，不编造新的算法测试通过数，也不为了格式整理创建代码审查代理。若改到可执行代码，再按AGENTS代码审查规则执行。

## 同步范围与维护成本

- 一个实质增量通常只改对应专题、执行看板和必要的一条演进记录；小错误提示/链接修补只改直接相关文档。不为“同步”而把结果复制到所有入口。
- README仅在用户可见能力、重要结论或入口变化时更新；项目规划仅在范围/里程碑/优先级实质变化时更新；CHANGELOG记录对外可见变化；索引仅在条目新增、迁移或用途/阶段变化时修改。
- 一般失败实验在原报告和看板记决定即可；只有重大模型、架构、硬件或范围取舍才新增ADR。不为每个小补丁、新测试或待办各建文档。
- 规范之间若冲突，优先消除旧表述，不能只在新段落追加例外，让后续代理重复旧流程。投入取舍遵循[项目代理规范](../AGENTS.md)的“决策价值与投入约束”。
