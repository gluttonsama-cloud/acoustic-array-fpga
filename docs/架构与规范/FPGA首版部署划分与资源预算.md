# FPGA首版部署划分与资源预算

> 文档类别：架构与规范｜状态：首版实现建议，未综合、未上板。2026-09-25。[返回文档索引](../文档索引.md)。

## 本轮要决定的事

在等待实录期间，先确定可复用的FPGA音频数据通路和实现预算，避免队友把仍在变化的定位/权重求解直接写进PL。最小交付是部署划分、可复算预算和必须保留的数值语义；到此停止，不扫描新声学参数、不假定器件或IP配置已确认。

这里的PS指板上处理器，PL指可编程逻辑。PC软件跑通不等于PS性能达标，也不等于嵌入式产品完成。

## 首版实施决定

先做“PC计算方向/权重＋PL持续处理音频”的联调路线。PL实现同步采集，再逐段实现加窗、FFT、可更新权重的复乘累加、IFFT和归一化重叠相加。PC负责人工方向输入、自动定位候选、校准和权重求解；自动定位声学门槛未过时仍能用人工指定方向联调三路音频，但不能把这种演示称为自动分离已通过。

PL不绑定DAS或MPDR求解器，只接收相同数学定义的权重。固定权重表示一段时间内保持不变，不表示烧死在逻辑里。阵列坐标变化通常只需重新校准/算权重；麦克风电气接口或采样时钟改变仍可能影响采集模块。

| 部分 | 第一阶段位置 | 后续推进依据 |
|---|---|---|
| 同步采集、抽取/滤波、样本计数、原始导出 | PL及实际前端 | 麦克风型号/时钟与采集实测 |
| 帧缓存、窗、FFT、三路加权、IFFT、重建 | PL逐级接入 | 先单位传递、再DAS、最后加载候选权重 |
| 校准、方向选择、定位、协方差和权重求解 | PC | 实录效果通过后，再评估移到PS的耗时/内存 |
| 显示、录音归档、调试 | PC | 不在首版扩展显示专用硬件 |

首版不将完整方向扫描表或MUSIC矩阵分解常驻PL。也不因为现有自动定位失败而增加FFT核或更换大FPGA：这两件事没有直接因果关系。当前没有足够证据指定升级板卡，最终资源是否够仍由实际型号与综合报告决定。

## 固定预算假设

仅计算一个明确工作点：48 kHz、16输入、3输出、512点FFT、256点帧移、257个单边频点。此处100 MHz只用作时钟预算示例，不是板卡承诺；位宽只用于容量比较，不是最终Q格式。

| 项目 | 计算 | 结果 |
|---|---|---|
| 帧更新率 | 48000/256 | 187.5帧/秒 |
| 每次帧移的处理期限 | 256/48000 | 5.333 ms |
| FFT/IFFT总次数 | (16+3)×187.5 | 3562.5次/秒 |
| 送入变换核的点数 | 19×512×187.5 | 1,824,000复数点/秒 |
| 波束复乘累加 | 257×16×3×187.5 | 2,313,000次/秒 |
| 原始16路PCM，32位容器 | 48000×16×4 | 3,072,000 bytes/s |
| 三路PCM，32位容器 | 48000×3×4 | 576,000 bytes/s |
| 完整单边谱回传，复数各分量32位 | 187.5×257×16×8 | 6,168,000 bytes/s |
| 三路权重单bank，各分量16位 | 257×16×3×4 | 49,344 bytes |
| 同样权重，各分量32位 | 257×16×3×8 | 98,688 bytes |
| 16位分量权重每秒更新10次 | 49344×10 | 493,440 bytes/s |

上述字节数均为有效载荷，不含协议、对齐、复制和突发间隙。10 Hz只是传输预算点，不是已经验证的跟踪/权重更新率。

**取舍：首版PC算法优先接收原始PCM，在PC自行作STFT；不要为了“FPGA已经算过FFT”就默认持续回传全部频谱。** 当前打包假设下，后者载荷是原始PCM的2.0078125倍。之后若PS/PC确实只需少量频带/低速统计量，再按定位需要定义抽取接口。

## 变换核数量和调度

首个待综合候选是可配置正反变换的共享FFT核，按16次正变换、3次逆变换分时调度；不是要求19个并行核。必须核对实际IP是否支持所选配置及切换时序，实测不够再拆成前向/逆向两核，而不是先堆并行度。

100 MHz时，每个帧移约533,333周期。若把70%时间作为19次变换的初始预算，则平均每次完整服务时间上限约19,649周期。这个70%是人为预留，服务时间必须包含输入/计算/输出、配置切换、等待和背压，不能只抄IP运算延迟。剩余时间不是自动证明其他模块能完成；最终提交整条调度路径的最坏耗时。

加权每帧需要12,336次复乘累加。若每周期能接收一个复乘累加，100 MHz下纯有效计算约0.12336 ms；若启动间隔为4，则约0.49344 ms，另加流水线排空/访存等待。一个复乘累加不等于一个DSP，访存端口和累加相关性可能决定实际启动间隔。

实施关口：稳态每5.333 ms处理一批新样本且不积压；启动延迟另测。软件当前首段有效输出需收到512个真实样本，约10.667 ms，再加前端滤波、计算、缓存和传输；不能用5.333 ms宣称整机端到端延迟。

## 不可省略的数值语义

1. 输出为 `Y[f,k] = sum_m conj(W[f,m,k]) * X[f,m]`。接口传W，PL做一次共轭；若改传已共轭系数必须更改格式声明，避免重复共轭。
2. 软件分析窗和合成窗均为周期Hann，帧移N/2。重叠相加之后要除以重叠窗平方和。稳态分母 `w[n]^2+w[n+N/2]^2` 在0.5到1之间，不能省略，也不能用固定乘2替代。省略会使单位传递路径出现约6.02 dB峰谷幅度起伏。这是重建实现问题，不是声学分离问题。
3. 稳态归一化可预计算倒数表减少逐样本除法；启动/结束有效区间必须依照现有补零与有效样本计数处理，不能假定所有输出位置都已有两个窗口。当前浮点实现见 `src/acoustic_array/dsp/stft.py`。
4. NumPy前向FFT不缩放、逆变换含1/N。实际IP的正逆变换、逐级缩放及块指数必须单独换算；不能因选择“IFFT”就假定振幅与NumPy相同。
5. 单边谱恢复完整谱须共轭镜像，DC/Nyquist保持实数；不是把257点直接送512点IFFT，或把负频部分补零。
6. 累加器位宽由实际权重范数与输入范围推导，不能把DAS的幅值界套到自适应权重。当前容量表不授权把系数量化成16位后直接上板。

## 权重更新和最小控制契约

复用现有接口的 `weight_set_id`、`source_ids`、`valid_from_frame`、格式版本。建议按频率→麦克风→输出排列，实虚交错；二进制格式仍需队友确认后冻结。

写入非活动bank→确认完整长度/格式→提交生效帧→PL仅在该帧起始切换。三路输出及该帧所有频点使用同一集合。不得计算一半时覆盖活动bank；迟到更新应报告拒绝或延期及实际生效帧，不能悄悄混用。首版固定权重联调不需要频繁切换，先保留这个边界。

控制最小状态包括：当前样本计数、谱帧编号、有效权重ID、实际生效帧、丢样/溢出计数、输出有效标志。权重原子切换只能防止半帧混用，不能保证听感无跳变；平滑策略属于后续动态更新验证，不在当前预算中宣称完成。

## 实现顺序与结束条件

- 采集关口：16通道顺序/同步/电平可查，原始WAV能被现有回放入口接收。
- 重建关口：用MIC7单位传递权重跑完整窗/FFT/IFFT/OLA，验证振幅、延迟、有效长度；先消除重建错误再评价波束。
- 加权关口：固定三方向DAS，按同一输入比较浮点与板端输出；然后加载候选权重。没有真实采集时可先用可追溯合成输入检验模块。
- 硬件关口：实际IP版本/配置、各级缩放位宽、最坏调度周期、综合资源、板端连续运行丢样与延迟全部留证。

算法侧已交付单位传递和三路DAS的浮点分级参考向量（见hardware/交付/分级参考增补包_20260925），包含输入PCM、窗后数据、单边谱、权重、输出谱及重建结果；用于先统一符号和归一化，不冠以板端逐位正确。收到IP配置后再给相匹配的定点模型和逐位向量。
