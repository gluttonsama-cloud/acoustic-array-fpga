# 队友开工与最小对接约定

版本：2026-09-25开工版。提交截止：2026-11-04。用途：启动可调整采集原型；不是最终PCB、器件选型或FPGA验收规格。

## 先看结论

现在可以并行开工，不等算法完全成熟。第一阶段交付是“16通道同步采集→缓存→导出→PC可读取”，不要求队友先实现自动定位。

算法侧已有方向估计、波束形成、多路输出和16通道WAV回放工具，已完成开发仿真与合成输入检查。复杂混响和近角分离仍有瓶颈，尚无真实阵列/板端效果验收。第一版目标是多路定向音频、方向展示和指定弱声增强，不承诺任意环境三人干净分离。

## 谁先做什么

| 负责人 | 现在开工 | 第一份交付 |
|---|---|---|
| FPGA队友 | 确认器件与IO，跑通共同采样基准、通道采集、缓存、导出、PC通信；暂无麦克风时先用计数测试数据联通传输 | 16通道原始文件、通道顺序、帧计数/丢样记录、采集参数 |
| 硬件队友 | 核对麦克风供电/接口/时钟要求、接线编号、可移动支架、实际坐标；配合固定位置录音 | 回填设备信息、通道坐标表及装配照片，首批控制录音 |
| 算法侧 | 提供数据约定、接收录音检查并回放，给出校准/效果结论；随后提供固定权重及参考输出 | 本包；拿到数据后的检查报告；下阶段数值对接包 |

先完成可复用的数据链，再接固定权重波束。器件变化可能修改时钟、驱动和接口，不能保证零返工；缓存、传输和波束主体尽量参数化。

## 已确定的数据约定

| 项目 | 本阶段约定 |
|---|---|
| 输入 | 同一采样基准下16通道、48,000 sample frames/s |
| sample frame含义 | 同一采样时刻的16个麦克风样本；不是FFT帧 |
| 逻辑编号 | MIC0～MIC15；算法参考为MIC7 |
| 通道顺序 | 最好WAV通道0～15对应MIC0～MIC15；实际不同时必须回填映射，禁止猜测 |
| 交付文件 | 优先单个16通道PCM24 WAV；PCM32可用，原链仅16bit时接受并记录；不交MP3/AAC |
| 原始性 | 不开AGC、降噪、AEC，不逐通道归一化，不独立裁剪/对齐；保留必要的PDM抽取与抗混叠滤波并记录配置 |
| 同步证据 | 共同采样时基/计数或等效证据；记录丢帧、补零、复位，不用“16个文件长度相同”证明同步 |
| 单文件时长 | 首批15～20秒，最长60秒（当前回放工具上限）；暂停写入后再交付 |

48kHz是PCM目标。原设计3.072MHz PDM、64倍抽取只是已有基线，必须依据实际麦克风允许时钟/采样边沿确认；本包不指定供电电压、FPGA引脚、IO电平或具体抽取滤波器参数，禁止直接照猜值接线。

## 传输与打包：建议先统一这个最小格式

下面是待FPGA队友确认的**推荐传输载荷**，不是声称当前硬件已实现的协议；已有可靠导出方式可保留，只要把其格式写清。

- 有符号二补码、little-endian、每通道样本32bit容器；样本按时刻交织：MIC0[n]…MIC15[n]，再MIC0[n+1]…MIC15[n+1]。
- 例如24个有效位放在容器低24位，高8位做符号扩展；元数据记录valid_bits=24、lsb_padding_bits=0。+8388607为0x007FFFFF，-8388608为0xFF800000，-1为0xFFFFFFFF。若实际为左对齐，记录真实移位，不静默转换。
- **原始32bit容器不等于PCM32 WAV的满量程编码。** 上述右对齐24bit转PCM32 WAV时应左移8位，或正确封装为PCM24 WAV；不能直接当PCM32写入导致约48dB的虚假变小。仅打包左移，不是增加有效位数或AGC。
- 每采样时刻64字节，有效载荷3,072,000字节/秒；20秒约61.44MB，不含包头。若以256个采样时刻分块，每块载荷16,384字节；分块大小可由队友按缓存调整，不绑定FFT参数。
- 分块传输至少能追踪块序号、首采样计数、有效sample frame数和丢样/溢出；不在这里另造复杂包头协议。通信方式由队友依现有板卡确定，持续有效吞吐须高于3.072MB/s并留协议余量，不能默认低速串口可承载完整数据。
- 首先交一个可独立读取的多通道WAV。若只可导出裸PCM，原样交回并附字节布局、有效位/移位/符号约定及帧数，由算法侧明确转换；当前回放入口不直接读取任意裸PCM。

## 阵列与安装：允许后续调整

坐标约定：面对正前方，+x向右、+y向前、+z向上；水平角atan2(x,y)，正前方0°，向右为正角。测量表用毫米，算法配置用米；原点取16只麦克风声学中心的质心，测量表可先用标记原点，由算法侧整体平移转换，不能改相对位置。

先做可移动固定件，供电/采集板与麦克风安装位置尽量解耦。已有线阵可以先用于采集和校准；无现成固定阵列时，预留约457.2mm横向跨度及60mm前后调整空间，结构外形另留安装余量。这里只是样机调整空间建议，不是新PCB尺寸。

包内“布局候选_非定版.csv”提供原线阵及仿真优选交错布局。交错布局y为±30mm，MIC7/MIC8保持y=0；这是候选，不能当已测坐标或正式制板文件。最终用“通道与坐标回填.csv”记录实际位置与对应接线。

**暂缓最终阵列PCB和外壳定型，不因软件音质不足直接升级FPGA；也不要先把完整NormMUSIC或MPDR求解器写死进PL。**

## 第一阶段回传与完成标准

先回填包内“设备与首批录音信息.json”和“通道与坐标回填.csv”。不知道的字段留null/空白，标清负责人，不编造型号或测试结论。元数据模板用于交流，不是直接传给回放工具的profile；算法侧会据实测表生成正式配置。

首批录音按[首批采集清单](真实十六通道采集清单.md)的1～4执行：20秒底噪、20秒正前方测试信号、-45°/0°/+45°各15秒单源，再20秒宽间隔三源。播放前保留2秒环境声；不同声源播放不同素材，保留原素材。暂时缺少多扬声器时，先交底噪和单源，不能为等三源一直不回传。

请一并发回：WAV、设备信息JSON、通道坐标CSV、一张标清正前方/编号的装配照片、源素材与位置记录、帧计数/异常日志。建议最高峰低于-6dBFS，不能削波；不同通道幅值有差异先记录，不自行调成一样。

第一阶段完成标准：文件可读且通道/采样率/样本数正确；有通道映射和实际坐标；零通道、重复通道、削波、丢样等异常有检查记录且未被隐瞒。采集链通过不代表算法或硬件最终验收。声学效果由算法侧回放后分别报告，不要求队友先证明三人分离成功。

## 现在需要队友确认的少量信息

板卡/FPGA完整型号、麦克风型号/数量/到货状态、采集接口与时钟边沿、供电/IO电平、现有阵列是否已制板、可用导出方式、第一批文件预计回传日期。请队友自己回填，算法负责人不必代查所有器件。

## 后续再交，不在这次要求队友实现

采集链稳定后，算法侧提供固定方向/权重、测试PCM与期望输出，约定FFT顺序、窗/帧移、缩放、位宽、舍入/饱和和权重更新接口。现有浮点参考不是FPGA逐位golden；这些数值细节需和实际IP配置一起冻结。优先PC求方向/权重，PL逐步接固定权重的数据通路；PC演示跑通不等于最终嵌入式部署已完成。
