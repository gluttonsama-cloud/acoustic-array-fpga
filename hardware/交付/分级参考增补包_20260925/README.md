# 分级参考增补包

2026-09-25。与此前“最小对接包”一起使用，无需替换已填写的设备或坐标表。

## 给谁、先做什么

主要给FPGA队友：先看本说明，再看[首版部署与资源预算](首版部署与资源预算.md)。硬件队友只需了解这次没有新增选型/布局要求，继续同步采集与实际坐标回填。

参考数据位于“参考数据”目录，格式和每个文件形状/哈希见[manifest.json](参考数据/manifest.json)。本包是浮点分级参考，不是RTL、定点逐位金标准，也不是实录或分离效果证明。长度2121样本（约44 ms），专门覆盖非整帧尾部；不能用于评价长时间不丢样或试听效果。

## 按这个顺序对照

1. 输入：`input_pcm_s24_in_s32.bin` 为2121×16个有符号int32，小端、时间优先、MIC0到MIC15。有效24位在低位，高位符号扩展，无文件头；除以2^23得到`input_pcm.bin`的float64数据。它不是PCM32 WAV的满量程打包。
2. 分帧：512点、帧移256，左补256个零；`frame_starts.bin`记录相对于原始PCM的起点，首帧为-256；不足部分补零。`window.bin`为周期Hann，`windowed.bin`为乘窗后的每帧16通道输入。
3. 正向FFT：`input_spectrum.bin`是未缩放RFFT单边谱，257点，不将单边幅度乘2。频率索引f对应 f×48000/512 Hz。
4. 单位传递：先使用`identity_mic7_weights.bin`。输出只有一路，应恢复原始MIC7；把这条链打通再测三路。
5. 三路DAS：`das_three_weights.bin`按频率、麦克风、输出排列；三输出对应-45°、0°、+45°。公式为 `Y=sum(conj(W)*X)`，文件里是W，不是已经共轭的系数。交错阵列只是仿真候选，完整坐标在manifest内，不用于照图制板。
6. 每种模式都给出`spectrum`（输出单边谱）、`inverse`（含1/N的逆变换）、`synthesis`（逆变换后再乘Hann）、`output`（归一化并裁剪到2121样本的输出）。`ola_denominator.bin`是有效输出样本的重叠窗平方和。
7. `chunk_lengths.bin`记录每个谱帧释放的有效输出长度；首帧释放0，最后仅保留真实长度。最终对齐索引不代表硬件零延迟。

所有二进制文件按C行优先展开，最后一维变化最快。浮点为little-endian IEEE754 float64；复数是交错的两个float64（real, imag），并不是16位或32位定点。整数类型以manifest的dtype为准。Python读取示例：`np.fromfile(path, dtype=entry['dtype']).reshape(entry['shape'])`。其他语言也须按形状和字节序解释，不要当文本打开。

输入是各通道不同的正弦、DC、Nyquist分量和脉冲，用于发现通道/符号/缩放错误；它不模拟三个人，也不应据输出大小解释空间分离性能。DC/Nyquist权重按项目约定取实部。

## 已核对与尚未核对

生成时以独立离线分帧/重叠相加对照现有流式实现，核对DAS相位公式与直接逐通道求和，并检查MIC7单位传递恢复。两种模式流式和离线输出最大绝对差均约4.16e-17。该误差只说明浮点实现一致，不是实际FFT IP容差。

队友拿到实际IP后需要回传：版本/架构、FFT与IFFT缩放、输入和系数位宽、舍入/溢出规则、输出顺序。算法侧再提供相匹配的定点模型；不要把本包float64直接截断后称为逐位参考。

## 复现与回传

在完整项目根目录执行：`.venv/Scripts/python.exe tools/export_handoff_vectors.py <新的输出目录>`。需要项目已有Python依赖；本增补包可直接读数据，不含完整运行环境。生成器拒绝覆盖已有目录；源文件哈希及依赖版本在manifest中。

联调异常请回传“出错级、文件名、帧/频点/通道索引、实际值、缩放说明”，无需先做完整算法移植。首批录音仍按原最小对接包采集，本包不增加新的录音条件。
